# ADS OS Design System

Обязательный визуальный язык интерфейсов Web, Telegram и MAX.
Источник: Master ТЗ v0.3 §119–151, Addendum v0.4 §19, §22.

Документ создан до продуктовых страниц, как требует v0.3 §151. Он описывает не
«как хотелось бы», а как реализовано в `packages/tokens` и `packages/ui`.

---

## 1. Принципы

1. **Монохромная основа.** Белый, чёрный, нейтральные серые. Цвет применяется
   только функционально: статус, риск, успех, предупреждение, выбранный элемент.
2. **Воздух вместо плотности.** Крупные интерактивные зоны, щедрые отступы,
   мягкие скругления, спокойные тени.
3. **Единая система, а не набор таблиц.** Продукт должен читаться как premium SaaS.
4. **Родство каналов.** Web, Telegram и MAX визуально узнаваемы как один продукт —
   за это отвечает общий словарь статусов в токенах.
5. **Смысл не кодируется одним лишь цветом.** У статуса всегда есть текстовая
   метка или иконка (v0.3 §139).

---

## 2. Токены

Единственный источник — `packages/tokens/design-tokens.json`. Компоненты
используют CSS-переменные и Tailwind-утилиты, порождённые из него, и никогда не
содержат raw-значений.

### Цвет

| Назначение                  | Токен                                              |
| --------------------------- | -------------------------------------------------- |
| Фон страницы                | `--color-bg` `#FFFFFF`                             |
| Вторичный фон               | `--color-bg-secondary` `#F7F7F8`                   |
| Поверхность карточки        | `--color-surface` `#FFFFFF`                        |
| Наведение / нажатие         | `--color-surface-hover` · `--color-surface-active` |
| Текст основной              | `--color-text-primary` `#0A0A0A`                   |
| Текст вторичный             | `--color-text-secondary` `#6B6B6B`                 |
| Текст отключённого контрола | `--color-text-disabled`                            |
| Декоративная граница        | `--color-border` · `--color-border-strong`         |
| Граница поля ввода          | `--color-border-input`                             |
| Основная кнопка             | `--color-cta` / `--color-cta-text`                 |
| Кольцо фокуса               | `--color-focus`                                    |

Статусы — четыре смысловых тона плюс нейтральный, каждый в трёх вариантах
(`--color-<tone>`, `-bg`, `-border`): `success`, `warning`, `critical`, `info`,
`neutral`.

> **Почему `text-disabled` не годится для подписей.** При соблюдении AA светло-серый
> текст почти сливается с `text-secondary`. Поэтому третьего уровня читаемого текста
> в системе нет: `text-disabled` используется исключительно для отключённых
> контролов, которые освобождены от требований контраста.

### Палитра графиков

Единственное разрешённое отступление от монохрома (v0.4 §19):

| Токен             | Значение  | Типичное назначение |
| ----------------- | --------- | ------------------- |
| `--color-chart-1` | `#0A0A0A` | Расходы             |
| `--color-chart-2` | `#6E68DE` | Лиды                |
| `--color-chart-3` | `#C97230` | Продажи             |
| `--color-chart-4` | `#2F8F63` | Выручка             |

Правила: без неона, без градиентов, одна метрика — один цвет во всём продукте,
статусные цвета с серийными не смешиваются.

> Референс дашборда рисует линии графика цветными, что на первый взгляд спорит с
> «цвет только функционально». Противоречия нет: различение серий — это и есть
> функция. Ограничение — ровно четыре приглушённых оттенка, зафиксированных в токенах.

### Типографика

Один шрифт — Inter (fallback: Manrope, системный стек). Смешивать семейства без
причины запрещено. Максимальный вес — 600: заголовки уверенные, но не тяжёлые.

| Роль                     | Размер / интерлиньяж / вес |
| ------------------------ | -------------------------- |
| `display`                | 36 / 1.15 / 600            |
| `h1`                     | 30 / 1.2 / 600             |
| `h2`                     | 23 / 1.25 / 600            |
| `h3`, заголовок карточки | 17 / 1.35 / 600            |
| `metric` (значение KPI)  | 28 / 1.15 / 600            |
| `body`                   | 15 / 1.55 / 400            |
| `body-sm`                | 14 / 1.5 / 400             |
| `caption`                | 13 / 1.45 / 400            |
| `micro`                  | 12 / 1.4 / 500             |

Минимум для основного текста Web — 14px, для вспомогательного — 12px. `micro`
применяется только там, где это действительно необходимо.

### Геометрия

Радиусы: `control` 12 · `small-card` 16 · `card` 20 · `hero-card` 24 · `pill` 999.
Отступы: 4 / 8 / 12 / 16 / 24 / 32 / 48.

> **Как записывать отступы в разметке.** Используется числовая шкала Tailwind,
> совпадающая с нашей сеткой один в один: `micro→1`, `xs→2`, `sm→3`, `md→4`,
> `lg→6`, `xl→8`, `2xl→12` (то есть `p-4` — это 16px). Именованные варианты
> (`p-md`, `gap-lg`) в тему Tailwind намеренно не выводятся: их имена совпадают
> с размерной шкалой, и `--spacing-md: 16px` молча превращал `max-w-md` в
> 16 пикселей — модальное окно схлопывалось в узкую вертикальную полосу.
> Сами значения по-прежнему доступны как CSS-переменные `--space-*` для
> потребителей вне Tailwind, включая конструктор сообщений ботов.

Тени только три и все мягкие: `card`, `raised`, `overlay`. Тяжёлый material-эффект
и glassmorphism запрещены. Рамки внутри рамок не допускаются — вложенность
показывается фоном и отступом.

### Движение

`fast` 140ms — наведение и нажатие · `normal` 200ms — появление карточек и
раскрытие · `panel` 280ms — панели и модальные окна.
Функция плавности — `ease-out` без заметного отскока.

Анимация обязана объяснять процесс, а не украшать. Критический алерт не мигает и
не создаёт стрессовой анимации. `prefers-reduced-motion` уважается: переходы
сокращаются практически до нуля, содержимое остаётся доступным.

## 3. Статусы

Словарь задан в токенах и общий для Web и ботов.

| Severity         | Подпись      | Тон      |
| ---------------- | ------------ | -------- |
| `critical`       | Критично     | critical |
| `warning`        | Важно        | warning  |
| `recommendation` | Рекомендация | success  |
| `info`           | Информация   | neutral  |

Состояния шага workflow: `completed` Готово · `active` В процессе · `waiting`
Ожидает · `blocked` Заблокировано · `error` Ошибка.

Статусы проекта, модуля, интеграции и доступности метрики — там же
(`vocabulary` в `design-tokens.json`).

Больше десяти разноцветных статусов система не допускает: смысловых тонов ровно
пять, остальное различается подписью.

---

## 4. Навигация

**Sidebar** постоянный, визуально лёгкий, иконка + текст. Активный раздел
выделяется мягким серым фоном, а не ярким цветом. На узких экранах сворачивается
в drawer, но остаётся предсказуемым. Только иконки для ключевой навигации не
используются.

Разделы (v0.3 §123): Главная · Проекты · Аналитика · AI-инструменты ·
Интеграции · Настройки.

**Topbar**: поиск, уведомления с бейджем, справка, профиль, контекстная кнопка
«Новый проект». Дополнительными действиями не перегружается.

**Внутри проекта** — каноническая навигация v0.4 §4. Бот показывает её сокращённо
и уводит на Web через deep link для сложных операций.

---

## 5. Дашборд

Главная отвечает на три вопроса: что происходит, что требует внимания, что делать
дальше. Помещается в 1–1.5 экрана desktop.

1. **KPI** — Расходы, Лиды, CPL, Продажи, Выручка. Крупное значение, динамика,
   мини-график.
2. **Динамика и AI-рекомендации** — большой график периода, рядом лента
   рекомендаций, разделённых по приоритету.
3. **Workflow проекта** — цепочка канонического жизненного цикла с состояниями.
4. **Нижний уровень** — интеграции, AI-помощник, уведомления.

> **Отступление от референса.** Макет рисует цепочку из 8 шагов; канонический
> lifecycle v0.4 §3 содержит 10. По правилу приоритета v0.4 §26 выигрывает
> lifecycle, поэтому `WorkflowStepper` реализован на 10 позиций с горизонтальной
> прокруткой.

### Карточка AI-рекомендации

Короткий конкретный заголовок · маленький бейдж статуса · причина в 1–3 строки ·
две кнопки: «Применить» и «Подробнее». Длинных AI-эссе в карточке нет: подробности,
evidence и ожидаемый эффект открываются в side panel. «Применить» для рискованного
действия запускает approval flow, а не выполняет действие немедленно.

---

## 6. Состояния экранов

**Empty** — объясняет, почему данных нет и что сделать дальше, и даёт действие.
**Loading** — skeleton вместо пустоты; для долгих процессов progress stepper с
реальным этапом («Собираем запросы», «Кластеризуем»).
**Error** — короткое объяснение без stack trace, кнопка повтора, для интеграции —
«Переподключить», технический `request_id` сохраняется для поддержки.

---

## 7. Доступность

- Контраст текста соответствует WCAG 2.1 AA; проверяется скриптом в CI.
- Статус не кодируется одним цветом — всегда бейдж, текст или иконка.
- Клавиатурная навигация и видимое состояние фокуса обязательны. Кольцо фокуса
  рисуется со смещением наружу, поэтому ложится на фон страницы и остаётся
  различимым в том числе вокруг чёрной кнопки.
- `aria-label` для контролов без текста.
- Тач-таргеты не меньше 44px.
- `prefers-reduced-motion` уважается.
- У графиков есть текстовые значения и подсказки.

---

## 8. Компоненты

Сначала переиспользуемые компоненты, затем страницы. Копировать разметку одной и
той же карточки по разным экранам запрещено.

Базовая библиотека (`packages/ui`, состав по v0.4 §22): Button, Input, SearchInput,
StatusBadge, MetricTrend, KpiCard, ProjectCard, RecommendationCard, AlertCard,
IntegrationCard, WorkflowStepper, DataTable, FilterBar, Modal, Drawer,
ConfirmationDialog, EmptyState, ErrorState, Skeleton, ChatComposer,
ProjectSwitcher.

Состояния для ключевых компонентов: `default / hover / active / disabled /
loading / error`. Для карточки рекомендации дополнительно `info / recommendation /
warning / critical`, для шага workflow — `completed / active / waiting / blocked /
error`.

Изолированный превью — Storybook, только для базовой библиотеки. Страницы
проверяются на demo-проекте в приложении (v0.4 §22).

---

## 9. Производительность

Тяжёлые анимации на больших таблицах не применяются. Не анимируется каждый элемент
при каждом обновлении данных. Графики загружаются лениво, длинные списки —
пагинация или виртуализация, изображения и скриншоты оптимизируются. Интерфейс
остаётся отзывчивым во время фоновых заданий. AI-стриминг допустим в чате, но
структурированные рекомендации выводятся только после валидации.

---

## 10. Запрещено

Яркий разноцветный градиентный SaaS-стиль · неоновый cyberpunk · тяжёлые тени ·
glassmorphism на каждом блоке · мелкий текст ради вместимости · десять и более
разноцветных статусов · перегруженные виджеты · скрытая без причины навигация ·
иконки без подписей для важных разделов · длинные AI-тексты в карточках ·
анимации, мешающие работе.

Отдельно: готовый admin-template без адаптации под эту систему не используется.

---

## 11. Definition of Done для UI

Страница считается готовой, если:

- [ ] использует design tokens, а не raw-значения;
- [ ] нет наложений, обрезки и переполнения текста;
- [ ] проверены desktop, tablet и mobile breakpoints;
- [ ] есть состояния loading / empty / error;
- [ ] есть клавиатурная навигация и видимый фокус;
- [ ] критические действия используют единый `ConfirmationDialog`;
- [ ] статусы не зависят только от цвета;
- [ ] компоненты переиспользованы, а не скопированы;
- [ ] нет сырого ответа API в интерфейсе;
- [ ] нет неконтролируемого горизонтального скролла, кроме предусмотренных таблиц.
