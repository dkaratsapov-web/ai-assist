# Готовность по ТЗ

Что из технического задания сделано, что осталось и что чем заблокировано.

Дата: 15 августа 2026. Сверено с `docs/architecture/v0.4-decisions.md`.

Роадмап из ТЗ (v0.4 §15):

```
MVP 0 Core → MVP 0.5 Research → MVP 1 Campaign Draft →
MVP 2 Live Ads + Measurement → MVP 2.5 Business Feedback →
MVP 3 Optimization → MVP 4+
```

Сейчас закрыты первые три.

---

## Сделано

### MVP 0 Core

- Монорепо, единые токены оформления, библиотека компонентов, Storybook.
- Изоляция данных между клиентами на уровне репозитория: чужой объект отдаёт
  «не найдено», а не «нет доступа».
- Проекты: создание, правка с защитой от перезаписи чужих изменений, удаление.
- Путь проекта из 10 шагов с подсказкой «что делать сейчас».
- Экономика целиком по v0.4 §5: обязательные и рекомендованные поля, режим
  неполной экономики, трёхсостоянческая разметка достоверности каждой величины
  (точно / приблизительно / нет данных).
- Слой AI с маршрутизацией задач между провайдерами и запретом на отправку
  персональных данных наружу. Работает на детерминированной заглушке.
- Генерация типов фронтенда из OpenAPI с проверкой расхождений в CI.
- Очередь фоновых задач, развёртывание одним `docker compose`.
- Вход через Яндекс ID, персональные учётные записи, роли, управление
  участниками, список активных входов, журнал действий.

### MVP 0.5 Research

- Краулер с сетевой изоляцией и защитой от обращений во внутреннюю сеть.
- Аудит посадочной страницы: балл, вердикт, замечания с конкретными действиями.
  Проверок семнадцать, включая политику обработки персональных данных —
  без неё Директ отклоняет объявления на модерации.
- История проверок и сравнение между собой: что исправлено, что появилось.
- Скрытие неактуальных замечаний с пояснением и автором. Критические скрыть
  нельзя.
- Конкуренты: разбор их страниц тем же кодом и таблица «чего нет у вас».
- Регулярная перепроверка сайтов раз в неделю с уведомлениями, когда стало хуже.

### MVP 1 Campaign Draft

- Семантика: разбор вставленного списка, отсев нецелевых по приоритету правил,
  сбор минус-слов, ручные решения переживают повторный импорт.
- Кластеризация вокруг общего смыслового ядра. Написан стеммер, отдельно решена
  беглая гласная («окно/окон»).
- Черновики объявлений: заголовок из ключевой фразы, текст из фрагментов самой
  посадочной страницы, проверка лимитов Директа и слов, из-за которых приходит
  отказ.
- Выгрузка кампании файлом для Коммандера — работает без доступа к API.
- Стратегия запуска: выбор стратегии ставок по ожидаемому потоку конверсий,
  срок и бюджет теста, блокировки по сайту и экономике.
- Отчёт по проекту для клиента одной печатной страницей.

## Осталось: заблокировано доступом к Директу и Метрике

Это MVP 2 и часть MVP 3. Без токена сделать нельзя — не потому что сложно, а
потому что неоткуда взять данные.

- **Публикация кампаний** прямо из системы вместо выгрузки файлом.
- **Статистика**: расход, клики, показы, поисковые запросы.
- **Метрика**: визиты и конверсии, проверка корректности целей и меток.
- **Атрибуция** (v0.4 §7): все продажи и CAC считаются через явно выбранную
  модель, смена модели версионируется и требует подтверждения.
- **Источники правды** (v0.4 §8): при расхождении чисел система не выбирает
  молча, а фиксирует расхождение с источником.
- **Свежесть данных** (v0.4 §9): финансовое действие не выполняется на устаревших
  данных.
- **Экраны аналитики и отчётов** на настоящих цифрах.
- **Поисковые запросы**: минус-слова из того, по чему реально показывались.
- **Автопилот** (v0.4 §10): все действия по умолчанию выключены, пороги
  достаточности данных задаются отдельно для каждого действия.
- **Прогноз** (v0.4 §6): три уровня зрелости, обязательные диапазон и
  достоверность. Прогноз без них не показывается никогда.

## Осталось: заблокировано другими вашими решениями

- **CRM и колтрекинг** (MVP 2.5). Без них экономика считается по заявкам, а не
  по продажам. Нужен выбор CRM и доступ.
- **Телеграм и MAX** — второй и третий каналы. ТЗ называет продукт
  мультиканальным, но каналы ждут вашего решения: свой бот или в составе.
- **AI-рекомендации, быстрый анализ, ассистент** — ждут выбора модели и ключа.
  Слой готов, переключается настройкой.
- **Тарифы и лимиты** — учёт потребления считается, но сколько это стоит
  клиенту, решаете вы.

## Чего в ТЗ нет и не будет

- Локализация: первый релиз только на русском (v0.4 §23), фреймворк локализации
  не подключается.
- ClickHouse: в MVP не используется (v0.4 §12).
- Платёжная система: в MVP не нужна (v0.4 §13).
