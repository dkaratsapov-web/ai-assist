# Подключение Яндекс Директа и Метрики

Пошаговая инструкция для схемы, которую мы выбрали.

Проверено по официальным материалам в августе 2026 года. Формулировки в
интерфейсе Яндекса время от времени меняются — если пункт называется чуть
иначе, ориентируйтесь на смысл.

---

## Наша схема

**Представитель.** Токен выпускается на один главный аккаунт. В каждом запросе
к API указывается, с каким рекламодателем система работает сейчас, — отдельный
токен на каждого клиента не нужен.

| Что             | Значение                                                        |
| --------------- | --------------------------------------------------------------- |
| Главный аккаунт | `audit-karatsapov`                                              |
| Первый клиент   | `sfera-vitamin`                                                 |
| Метрика         | Счётчик клиента открывается гостевым доступом главному аккаунту |

Схема расширяется без изменений в коде: каждый следующий клиент — это ещё один
логин в списке, а не ещё один токен.

---

## Шаг 1. Дать главному аккаунту доступ представителя

Со стороны клиента `sfera-vitamin`: в интерфейсе Директа открыть управление
доступами и добавить `audit-karatsapov` как представителя.

Это делается в самом Директе и не требует ни разработки, ни API. Если доступ
уже выдан и вы видите аккаунт клиента при переключении в интерфейсе — шаг
пройден.

**Проверка:** зайдите под `audit-karatsapov` и убедитесь, что можете
переключиться на `sfera-vitamin`. Знать пароль клиента недостаточно — через API
работает только настоящая выдача доступа.

---

## Шаг 2. Зарегистрировать приложение

Приложение — это способ Яндекса понять, кто именно ходит в API. Регистрируется
один раз.

1. Войти под учётной записью **`audit-karatsapov`** — чтобы приложение и токен
   принадлежали одному аккаунту и потом не пришлось разбираться, чей он.
2. Открыть <https://oauth.yandex.ru/client/new>
3. Название — любое понятное, например `ADS OS`
4. Платформа — **веб-сервисы**
5. **Redirect URI** — на первое время указать
   `https://oauth.yandex.ru/verification_code`. Это служебный адрес Яндекса: он
   позволяет получить токен вручную, без работающего сервера. Позже добавим
   второй адрес на `ai-helper.pro`, когда появится вход через кнопку.
6. В правах отметить:
   - **«Использование API Яндекс.Директа»** — это Директ;
   - **«Получение статистики, чтение параметров своих и доверенных счётчиков»** —
     это Метрика. Слово «доверенных» здесь ключевое: именно под него попадает
     счётчик клиента, открытый вам гостевым доступом.
7. Создать.

На выходе Яндекс покажет **ClientID** и **пароль приложения (Client secret)**.

ClientID понадобится на следующем шаге. Пароль приложения — секрет, он нужен
будет только на сервере.

---

## Шаг 3. Подать заявку на доступ к API

Без одобренной заявки запросы к API не выполняются.

Подавать от аккаунта `audit-karatsapov`, указав ClientID из шага 2.

**Тип заявки — «Тестовый доступ».** Это осознанный выбор, а не осторожность:
тестовый доступ открывает Песочницу — среду, которая имитирует API Директа, но
полностью изолирована от настоящих кампаний и денег. Ровно там интеграция и
должна писаться. Боевой доступ запрашивается отдельно и позже, когда будет что
подключать и когда пройдут проверки безопасности.

Сроки рассмотрения Яндекс не обещает. Тестовый доступ обычно открывают быстрее
боевого.

---

## Шаг 4. Получить токен

После одобрения заявки — получить OAuth-токен для `audit-karatsapov`. С
Redirect URI из шага 2 это делается вручную в браузере, без сервера.

Токен долгоживущий: перевыпускать его каждый день не придётся.

---

## Шаг 5. Положить токен на сервер

**Токен не пересылается в переписке — ни в чат, ни в почту, ни в мессенджер.**
Он даёт доступ к рекламным бюджетам, вашим и клиентским. Переписка хранится и
может быть прочитана.

Правильный путь: вы сами вписываете значения в файл `infra/.env` на сервере.
Заготовка уже есть — см. `infra/.env.example`:

```
YANDEX_DIRECT_LOGIN=audit-karatsapov
YANDEX_DIRECT_TOKEN=          ← сюда
YANDEX_DIRECT_SANDBOX=true
YANDEX_METRICA_TOKEN=         ← сюда
```

Система читает их сама. Мне доступ к ним не нужен ни на каком этапе.

---

## Что происходит дальше

Интеграция пишется и отлаживается на Песочнице. Переключатель
`AD_PLATFORM_ADAPTER` при этом остаётся в положении `mock` до тех пор, пока не
пройдут проверки безопасности (v0.3 §114) — то есть система не пойдёт в
настоящий кабинет, даже если токен уже лежит на сервере. Это не перестраховка,
а разделение двух разных событий: «токен получен» и «системе разрешено тратить
деньги».

---

## Открытый вопрос, который проверяется в Песочнице

Для доступа к данным рекламодателя логин передаётся в заголовке `Client-Login`.
Для агентской схемы это описано однозначно; для схемы представителя нужно
убедиться на практике, какой именно логин там ожидается — рекламодателя или
его пользователя.

Проверяется это одним запросом в Песочнице, без всякого риска. Отдельного
действия от вас не требует — упомянуто, чтобы вопрос не потерялся.
