# @ads-os/ui

Библиотека переиспользуемых компонентов ADS OS. Состав — по v0.4 §22: примитивы
и карточки, но не страницы.

## Правила

- Raw-значения цветов, отступов и таймингов в компонентах запрещены — только
  токены из `@ads-os/tokens`.
- Разметка одной и той же карточки не копируется по экранам (v0.3 §142).
- У каждого статуса есть текстовая подпись; цвет только усиливает её (v0.3 §139).
- Контрол без видимого текста обязан иметь `aria-label` — в `IconButton` это
  обязательный параметр, а не необязательная добавка.

## Решения, которые стоит знать

**`cn()` настроен под нашу шкалу шрифтов.** `tailwind-merge` по умолчанию не знает
кастомных размеров и относит `text-caption` (размер) и `text-cta-text` (цвет) к
одной группе, оставляя только последний. На практике это давало чёрный текст на
чёрной кнопке — цвет молча выбрасывался. Поэтому `cn()` расширен списком размеров
из `design-tokens.json`. Проверка контраста такое не ловит: палитра корректна,
ломается склейка классов.

**Кольцо фокуса всегда со смещением наружу.** Оно ложится на фон страницы, а не на
сам контрол, и поэтому остаётся различимым в том числе вокруг чёрной кнопки.

**`Modal` и `Drawer` построены на нативном `<dialog>`.** Браузер сам удерживает
фокус, закрывает по Esc и делает фон инертным — собственная фокус-ловушка была бы
и объёмнее, и хуже.

**`MetricTrend` требует `polarity`.** Направление не говорит, хорошо это или
плохо: рост выручки — успех, рост CPL — проблема. Параметр обязательный, чтобы
нельзя было случайно покрасить ухудшение в зелёный.

**`LineChart` умеет две оси и измеряет контейнер.** Рубли и штуки на общей шкале
несопоставимы — меньшая метрика вырождается в прямую линию. Ширина берётся через
`ResizeObserver`, иначе на узком экране SVG масштабирует вместе с графиком и
подписи осей, и они становятся нечитаемыми.

**`KpiCard` знает о недостоверных данных.** Состояния `proxy` и `unavailable`
показывают, что метрика посчитана по временному заменителю или что источник не
подключён. Правдоподобное число здесь хуже честного пробела.

## Storybook

```bash
pnpm storybook          # http://localhost:6006
pnpm build-storybook
```

Истории лежат рядом с компонентами (`*.stories.tsx`) и покрывают состояния из
v0.3 §143: `default / hover / active / disabled / loading / error`, для карточки
рекомендации дополнительно четыре уровня severity, для шага workflow — пять
состояний.

Шрифт в Storybook отличается от приложения: Inter подключается через `next/font`
и в статической сборке Storybook недоступен, поэтому применяется системный
запасной стек из токенов. На проверку компоновки и состояний это не влияет.
