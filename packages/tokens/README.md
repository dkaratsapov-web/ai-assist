# @ads-os/tokens

Единый источник визуальных параметров ADS OS (v0.3 §141, v0.4 §19).

```
design-tokens.json ──▶ dist/tokens.css  (CSS-переменные в @theme Tailwind v4)
                   └─▶ dist/tokens.ts   (типизированные константы + словарь статусов)
```

## Правило

Цвета, отступы, радиусы, тени, тайминги и статусные подписи меняются **только** в
`design-tokens.json`. Raw-значения в компонентах запрещены: расхождение между Web и
сообщениями ботов возникает именно так.

Файлы в `dist/` сгенерированы и не редактируются — они перезаписываются сборкой и
не попадают в git.

## Команды

```bash
pnpm --filter @ads-os/tokens build            # пересобрать
pnpm --filter @ads-os/tokens check:contrast   # проверить контраст
```

## Проверка контраста

`check-contrast.mjs` выполняет 34 проверки и запускается в CI. Правка палитры,
роняющая контраст ниже порога WCAG 2.1 AA, ломает сборку.

Две тонкости, заложенные в проверку намеренно:

- **Декоративные границы не проверяются на 3:1.** Карточка опознаётся по фону и
  тени, поэтому `border` держится светлым, как требует v0.3 §121. Отдельный токен
  `border-input` для полей ввода проверяется — там граница является единственным
  признаком контрола (WCAG 1.4.11).
- **Различимость серий графиков измеряется через ΔE, а не через коэффициент
  контраста.** WCAG сравнивает только яркость: приглушённые фиолетовый и оранжевый
  дают около 1.1, хотя различаются очевидно. Порог ΔE ≥ 25.

## Словарь статусов

`vocabulary` в `design-tokens.json` задаёт подписи и смысловую окраску для severity,
состояний шага workflow, статусов проекта, модуля и интеграции, а также доступности
метрики. Один и тот же словарь используется Web-компонентами и сообщениями ботов,
поэтому «Критично» в интерфейсе и в Telegram — это гарантированно одно и то же слово.

Цвет никогда не является единственным носителем смысла: у каждого статуса есть
текстовая метка (v0.3 §139).
