# Module Spec — Economics Engine

Шаблон по v0.4 §21. Одна страница до кода, а не проектный документ.

## 1. Purpose

Считать экономику проекта и честно сообщать, каким её выводам можно доверять.
Все дальнейшие рекомендации обязаны учитывать экономику (v0.3 §19), а
оптимизация по CAC и марже возможна только при полных данных (v0.4 §5).

## 2. Input

| Категория       | Поля                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------- |
| Обязательные    | `monthly_budget`, `average_order_value` либо `expected_value`, `main_conversion`            |
| Рекомендованные | `margin_percent`, `lead_to_sale_rate`, `target_cac`, `target_cpl`, `target_marketing_share` |

Ввод пользовательский. Из сайта эти величины не извлекаются, и AI-бриф не
изображает обратного (v0.4 §5).

## 3. Output

`EconomicsSummary` — набор метрик, у каждой три возможных состояния:

- `available` — посчитано по данным пользователя;
- `proxy` — посчитано с использованием допущения по умолчанию, значение
  ориентировочное;
- `unavailable` — исходных данных нет, число не показывается.

Метрики: валовая прибыль со сделки, безубыточные CAC / CPL / ROAS, целевые
CAC / CPL / ROAS, ёмкость бюджета по лидам и продажам, прогноз выручки и
валовой прибыли.

Дополнительно: `mode` (`complete` / `limited` / `insufficient`), список
незаполненных полей и подсказка, что заполнить для разблокировки оптимизации по
продажам.

## 4. Data Model

`ProjectEconomics` — одна запись на проект, все денежные величины в `Numeric`.
Расчёт на `float` даёт накопленную ошибку, а речь о деньгах клиента.

Версионируется (`version`) — изменение экономики меняет все производные
рекомендации, и нужно понимать, на какой версии готовилось согласование.

## 5. External APIs

Нет. Это единственный модуль ядра без внешних зависимостей — поэтому он и
делается первым.

## 6. Side Effects

Нет. Чистые функции: те же входные данные дают тот же результат. Запись в БД —
ответственность вызывающего слоя, не расчёта.

## 7. Failure / Retry

Отказов нет. Некорректные значения (отрицательный бюджет, маржа вне диапазона,
конверсия больше единицы) отклоняются валидацией на входе, а не приводят к
бессмысленному результату.

## 8. Permissions / Security

Чтение — любая роль с доступом к проекту. Запись — `OWNER` и `SPECIALIST`
(v0.3 §4). Персональных данных не содержит, в режим `SENSITIVE` не попадает.

## 9. Audit Events

`economics.updated` с указанием изменённых полей и версии. Само изменение
экономики не является денежным действием, но меняет пороги всех последующих —
поэтому фиксируется.

## 10. Tests

Модульные тесты на:

- корректность формул на эталонном примере, посчитанном вручную;
- три режима полноты и переходы между ними;
- честность состояний: при отсутствии маржи CAC не появляется ни в каком виде;
- краевые случаи: нулевая маржа, конверсия 100%, отсутствие среднего чека при
  заданной ожидаемой ценности;
- отклонение некорректных значений.
